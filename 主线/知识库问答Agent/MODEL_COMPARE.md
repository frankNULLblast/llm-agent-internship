## 差异题（结论最集中的地方）


### 第 3 题：什么是大模型幻觉？

- **deepseek-v4-flash** → passed=True，来源=['llm.md']
  - 回答：根据提供的资料，大模型可能生成听起来合理但事实错误的内容，这种现象常称为**幻觉**。关键事实需要通过可靠资料或工具核验。
- **deepseek-v4-pro** → passed=False，来源=['llm.md']
  - 回答：大模型幻觉是指模型生成的内容听起来合理可信，但实际上与事实不符或缺乏依据。这种问题源于模型的工作原理——它基于训练数据和输入，生成概率较高的后续内容，而非真正理解或验证事实。因此，关键事实需要通过可靠资料或工具进行核验。

### 人工判读（重要，不能只看分数）

第 3 题 `pro` 判为不通过，**不是它答错了，而是自动指标扣的是用词**：

- 评分要求 `must_contain = ["事实错误"]`，靠字符串匹配。
- `flash` 沿用了资料原句「听起来合理但**事实错误**」，字面命中。
- `pro` 改写成「与**事实不符**或缺乏依据」，还补充了成因（基于概率生成、并非真正理解或验证事实）。语义完全正确，信息量更大，但因为没出现「事实错误」四个字，`keyword_hit = False`。

两条结论：

1. **模型层面**：`pro` 倾向重述与展开，`flash` 倾向贴着原文复述。做 RAG 抽取式问答时，贴原文反而更容易过自动评测；要解释性输出时 `pro` 质量更高。
2. **评测层面**：`keyword_hit` 是**代理指标**，只能筛明显跑题，不能判语义对错。这次 90% vs 100% 的差距全部来自措辞，而非能力。要真正比语义，得换成人工抽查或 LLM-as-judge（让第三个模型当裁判打分），这也是本项目下一步的改进方向。

## 怎么读这张表

- **拒答题两模型必然同分且 token=0**：拒答发生在检索层（检索为空且非算术即拒），压根没到模型，所以拒答正确率不体现模型差异。
- **通过率相同不等于两模型一样**：还要看 token 成本与延迟；同样答对，便宜快的更适合线上。
- **keyword_hit 是代理指标**：只查关键词是否出现，不代表语义正确，差异题需人工读原答案（已存于 `model_compare.json`）。
- 想让对比更有区分度，就往 `test_questions.json` 里加多跳推理题、易混淆题，而不是加更多简单事实题。
