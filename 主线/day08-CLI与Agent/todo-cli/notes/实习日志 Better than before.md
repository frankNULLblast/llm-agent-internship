# Day 8 实习日志 · Better than before

## 今日目标
从一份可验收需求出发，用编码 Agent（WorkBuddy）完成一个 JSON 持久化的待办 CLI，并体会"先计划、后实现、靠验收命令和 git diff 验证"的协作纪律。

## 过程记录

### 1. 先把模糊需求变成可验收条件
一开始脑子里只有"做个待办程序"这种模糊说法，按教程要求写成了 `SPEC.md`：四条命令各自给了输入、输出、错误和退出码，数据落 `todos.json`（UTF-8），且只用标准库。这一步最关键——**把"做一个待办程序"这个模糊需求，改成了"四条命令产生四条可核对结果"的可验收条件**。之后所有实现都拿 SPEC 当尺子，Agent 想擅自加东西也有据可拒。

### 2. Agent（WorkBuddy）先计划，我确认
我让 Agent 读取 SPEC、把需求拆成 5 个最小任务（数据层+参数骨架 / add / list / done / delete），每个任务配一条验收命令，先不动手。计划经我确认后才开始写 `todo.py`。

### 3. 实现与验收
按计划写出 `todo.py`（纯标准库），跑教程固定的验收序列：

```
暂无待办
已添加 ID 1
已添加 ID 2
[ ] 1: 阅读 Agent 文档
[ ] 2: 完成 Python 练习
已完成 ID 1
已删除 ID 2
[x] 1: 阅读 Agent 文档
错误：不存在 ID 99      ← 走 stderr，退出码 1
```

三个错误分支也单独验了：空内容、非整数 ID、不存在的 ID，全部中文报错 + 非 0 退出码；重启新进程后 `todos.json` 数据还在，持久化达标。

### 4. 挑战任务 clear-done
先更新 SPEC 加 `clear-done`，再改代码：删掉所有 done=true 的事项并打印数量。验证删 2 留 1、空库删 0，都符合预期。

## 需人工审查的点
- `next_id` 取现有最大值 +1，删除最高 ID 后该 ID 会复用——这是教程明确允许的局限，已在代码注释/笔记里记录。
- 本地模型（Day7 的 Codex 实验）和本项目是两回事：Day 8 我就用 WorkBuddy 当编码 Agent，没再拉 Codex。

## 验收清单
- [x] SPEC.md 含输入、输出、错误、约束
- [x] Agent 先计划后实现，改动范围可控
- [x] 四条命令均可运行，重启后数据仍在
- [x] 错误写 stderr 且退出码非 0
- [x] 不依赖数据库或第三方包

## 模糊需求 → 可验收条件（每日总结必填）
"做一个待办程序" → SPEC.md 里四条命令各自定义输入/输出/错误/退出码，数据持久化到 todos.json；验收用固定命令序列对照预期输出，而不是凭感觉说"能用"。
