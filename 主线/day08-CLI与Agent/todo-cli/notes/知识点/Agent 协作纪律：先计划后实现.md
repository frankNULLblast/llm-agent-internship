# Agent 协作纪律：先计划后实现

> 一句话：Agent 说"完成"不算证据，验收命令和 git diff 才是。

## 协作顺序（Day 8 用的）
1. **说目标边界**：把 SPEC 给 Agent，约束写死（只用标准库、实现放 todo.py、数据固定 todos.json、错误写 stderr）
2. **让 Agent 先读和计划**：拆最小任务，给每个任务配一条验证命令，**先不编辑**
3. **人审核**：计划过了再放手
4. **小步执行**：一次只做一个任务，跑验收命令
5. **看证据**：每次 `git diff` 核对改动范围，不靠嘴说
6. **跑测试验证**：本项目用固定命令序列对照预期输出

## 为什么这样
- 计划阶段就把范围框死，Agent 不容易"改需求"或过度重构
- 小步 + 每步验证，出问题能定位到是哪一步
- `git diff` 是客观证据，比"我改好了"可信

## 和 Day 7 的关系
Day 7 对比 Codex / WorkBuddy 的协作方式，Day 8 直接拿 WorkBuddy 当编码 Agent 实操这套纪律。两者内核一致：**人掌舵，Agent 划桨，验证靠命令和 diff**。
