# 可验收需求与 SPEC

> 一句话：需求写出来要能"对或错"，而不是"感觉行"。

## 模糊需求为什么不行
"做一个待办程序"无法验收——做到什么程度算完？加功能加到哪算停？没有边界，Agent 也容易跑偏。

## 可验收需求的写法
给每条命令定义四样东西：
- **输入**：用户敲什么
- **输出**：屏幕显示什么
- **错误**：什么情况报错、报什么、退出码几
- **数据位置 / 约束**：存哪、用什么技术

本项目写成 `SPEC.md`：
- `add "内容"` → 返回整数 ID
- `list` → 按 ID 显示
- `done ID` / `delete ID` → 改/删存在的项
- 数据落 `todos.json`（UTF-8），只用标准库
- 空内容 / 非整数 / 不存在 ID → 中文错误 + 非 0 退出码

## 为什么有效
有了 SPEC，验收就变成"跑固定命令序列对照预期输出"，而不是靠主观判断。Agent 想擅自加需求，也能拿 SPEC 挡回去（"只接受与验收标准一致的实现"）。
