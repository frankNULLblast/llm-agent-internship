# Skill 阅读练习分析

## SKILL.md 四问

### 1. 触发条件是什么？
用户要求把学习笔记整理为摘要和自测题时触发。description 字段就是触发条件的自然语言描述，Agent（如 WorkBuddy / Codex）根据它判断"当前请求是否该用这个 Skill"。

### 2. 允许读取什么？
只读取用户明确指定的笔记。不是"所有 .txt"，不是"某个目录下全部文件"，而是用户点名要的那几篇。这是一个最小权限原则。

### 3. 输出是什么？
三条摘要 + 三道自测题。数量固定，格式明确。摘要要从原文提炼，不能编造。

### 4. 失败边界是什么？
- 不确定的信息标记为"原文未说明"——不猜、不补
- 完成前逐条检查摘要能否在原文找到依据——自检环节
- 没有说"如果找不到笔记怎么办"——隐含的失败边界是"笔记不存在就不做"

## Skill vs MCP Server 对比

| 维度 | Skill (study-note-summary) | MCP Server (study-tools) |
|------|---------------------------|--------------------------|
| 层级 | 应用层（指令/流程规则） | 传输层（可调用外部能力） |
| 形态 | Markdown 文本（YAML frontmatter + 正文） | Python 代码（FastMCP 框架） |
| 约束方式 | 软约束——靠模型遵循文本指令 | 硬约束——代码级白名单和路径校验 |
| 能做什么 | 告诉模型"该做什么、怎么做、怎么检查" | 提供可调用的函数和只读资源 |
| 安全边界 | "只读取用户明确指定的笔记"——靠模型自觉 | 固定 ROOT 目录 + 字符校验 + resolve 后路径比对——代码强制 |
| 失败处理 | "标记为原文未说明"——模型自行判断 | 返回错误字符串——函数级返回 |

### 关键区别：两者不是同一层

Skill 是"做事的方法论"——它规定流程（先读、再摘要、再出题、最后自检），但不提供任何代码能力。如果模型读了 Skill 但没有工具，它只能靠自己已有的文件访问能力（如果有的话）去读笔记。

MCP Server 是"做事的能力"——它提供 search_notes 工具和 note_index / get_note 资源，是实打实的代码函数。但它不规定"搜到之后该怎么整理"。

### 两者可组合

最优解是组合使用：Skill 告诉模型"用 study-tools 的 search_notes 工具去搜笔记，搜到之后按三条摘要 + 三道自测题的格式输出"，MCP Server 提供搜索这个能力本身。Skill 是"大脑的指令"，MCP Server 是"手的动作"。

### 安全性的差距

Skill 的安全约束是文本级的——"只读取用户明确指定的笔记"这句话，模型可能遵守也可能不遵守，没有代码兜底。MCP Server 的安全约束是代码级的——固定 ROOT 目录、拒绝路径穿越字符、resolve 后路径比对，三层校验，模型绕不过去。

这就是为什么生产环境中不能只靠 Skill 做安全控制，必须有 MCP Server（或等价的代码工具）来兜底。
