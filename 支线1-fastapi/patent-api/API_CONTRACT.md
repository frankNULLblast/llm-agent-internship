# API 契约（v0.1.0）

> 脱离 Swagger 的一页契约速查。所有请求/响应均为 JSON，服务只监听 `127.0.0.1:8000`，全部数据为虚构教学样例。

| 接口 | 方法 | 请求体 | 成功响应（200） | 错误码 | 领域边界 | 固定测试 |
|---|---|---|---|---|---|---|
| `/health` | GET | 无 | `{"status":"ok","version":"0.1.0"}` | — | 仅健康检查，无副作用 | `test_health` |
| `/api/v1/fees/summary` | POST | `fees.json`（3 条记录） | `{"total_yuan":"5600.50", ...}` | `400` 非法金额 / 错误费用申请号 | 复用 `calculate()`，金额由 `Decimal` 计算 | `test_fees_*` |
| `/api/v1/patent-bills/review` | POST | `bill_record.json`（9 字段） | 人工复核分流结果 | `422` 缺字段/类型错；`400` 领域值错 | 复用 `build_result()`；标准/优先均须人工复核 | `test_review_*` |
| `/api/v1/patent-bills/recognize` | POST | OCR 文本（`{"ocr_text": "..."}`） | 结构化票据 | `503` 提取器不可用；`502` 上游解析失败 | Day 4 挑战；离线假提取器，**不调用模型** | `test_recognize_*` |

## 状态码语义

- `200`：成功完成计算或复核分流。
- `400`：请求形状正确，但违反领域规则（金额非法、申请号格式错）。
- `422`：字段、类型或 JSON Schema 不符合接口要求（缺字段、多余字段、类型错）。
- `500`：未预料的服务端缺陷（不是业务规则问题）。

## 为什么成功仍用 200

两个 POST 都是「接收请求→校验→计算/分流→返回结果」，属于同步处理完成，不是「创建资源」，因此用 `200` 而非 `201`。低置信度票据也返回 `200`，因为它确实完成了复核分流，只是结果指向「优先人工复核」，并非失败。
