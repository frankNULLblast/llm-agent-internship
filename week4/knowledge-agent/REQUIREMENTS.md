# 知识库问答 Agent 需求

## 用户
大一计算机专业学生。

## 必须功能
1. 读取 `knowledge/` 中 UTF-8 的 Markdown/TXT。
2. 检索相关片段；回答时显示来源文件。
3. 资料不足时输出“资料不足，无法回答。”
4. 支持一个只计算加减乘除的受控计算器工具。
5. 保留工具日志、测试问题和批量评测结果。

## 非目标
无网页界面、数据库、向量数据库、多智能体、云部署和长期记忆。

## 命令
`python agent.py "问题"`
`python eval.py test_questions.json`
`python -m unittest discover -v`

## 项目范围说明

### 保底能力
命令行下能用固定的三条命令跑通：单问、批量评测、离线测试。资料只来自 `knowledge/` 三份脱敏 Markdown，回答必须带来源文件名，检索不到就明确拒答。整个流程只依赖 Python 标准库加一个 DeepSeek 兼容的 OpenAI 客户端，不引入检索框架。

### 明确不做
不做网页界面、不接数据库、不上向量库、不做多智能体协作、不部署到云上、不保留跨会话的长期记忆。这些都是第 4 周之后的话题，现在加进来只会让验收变得说不清。

### 最大的已知风险
资料只有三份，覆盖面很窄，"能回答"和"该拒答"的边界很容易被问题措辞带偏。10 条验收问题里放了 2 条必须拒答的，就是为了盯住这条边界——如果哪天改了检索阈值，拒答的那两条会最先失守。第二个风险是关键词检索本身没有语义能力，问题换个说法就可能命中不到，Day 18 调参时要拿这 10 条当标尺。
